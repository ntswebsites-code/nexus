# GAP VS NEXUS API (from the 5B draft)

Nexus API baseline: `docs`-independent audit `backend-audit.md` (sections 1 and 2): 140 route handlers; investor portal routes under `/api/v1/investor/*`; data model of 55 tables with no `funds`, `fund_commitments`, `units`, NAV, dealing, notice or LP-ledger entity; no `Idempotency-Key` handling; no pagination; no export; no realtime; error body `{error:{code,message,details}}`; list body `{data, total}`. Statuses: **Covered** = a Nexus endpoint already does the same job and only an adapter is needed; **Partial** = a related endpoint or entity exists but the contract differs materially; **Missing** = nothing exists.

Cross-cutting gaps that affect every row:

- Envelope: the UI expects `{success, message, data, timestamp, meta.requestId}` and list data `{items, page, pageSize, total, totalPages}`; Nexus returns bare payloads or `{data,total}`. FR-LP-109: add a response adapter for `/api/v1/lp-portal/*` — AC: every route returns the envelope.
- Errors: the UI reads `fieldErrors`, `code`, `retryable` and a message; Nexus returns `{error:{code,message,details}}` with snake_case codes. See ROLES & PERMISSIONS and corrections 9.6.
- Idempotency: nine write routes need `Idempotency-Key` (acknowledge call, payment confirmation, subscription, redemption, performance report job, acknowledge notice, create request, bank-instruction change, invite colleague); Nexus has none (backend-audit H8).
- Pagination: Nexus lists are unpaged (`take` 200 to 500); the LP lists need `page` and `pageSize` (default 50, max 200).
- Fund entity: Nexus has no fund; `capital_events.investmentName` and `snapshot_investments.name` are free text. Everything fund-scoped (session, dashboard, calls, distributions, dealing, performance, documents, notices, requests, threads) needs a `funds` table and per-membership `fundIds`.
- Valuation status, as-of date, share class and operating model are not stored anywhere in Nexus; `investor_snapshots.valuationDate` is the only as-of concept and has no status.
- Money and units: Nexus stores DECIMAL(20,4) amounts and VARCHAR quantities; the LP contract needs units (6 dp) and NAV per unit (8 dp) as decimal strings.
- Downloads: Nexus returns signed URLs (`download-url`); the UI calls blob endpoints and saves them with a file name. Either add streaming endpoints or change the UI to follow the URL (Q-NEW).
- Uploads: `POST /api/v1/uploads` produces orphan ids; the LP flows need upload-then-attach (requests, replies) and multipart-with-fields (payment confirmation, subscription).
- Audit: LP actions to audit (acknowledgements, dealing submissions, document views and downloads, bank-change requests, colleague changes) — Nexus audits some downloads and requests; thread messages and document reads are not audited.
- Notifications: Nexus notifies staff on investor actions through the outbox; the LP bell needs the three feed sources and the preference switches honoured.
- Staff side: almost every investor-facing entity needs a staff publish/maintain path; see STAFF-SIDE COUNTERPARTS.
