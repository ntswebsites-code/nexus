# 8-NFR-GAPS (from the backend draft)

- **DEF-513** **Idempotency not implemented.** `Idempotency-Key` is accepted by CORS but ignored, so repeated POSTs create duplicate capital events, documents and requests. — AC: a repeat POST with the same key within 24 h returns the original response and creates no new row.
- NFR-PERF-005: **Pagination** on every list endpoint (`page`, `pageSize` ≤500, default 50; response `{data, page, pageSize, total}` where `total` is the full count). Today lists are silently capped at 200–500 rows and `total` equals the returned length. — AC: a list with 600 rows returns total 600 and pages through all of them.
- **DEF-514** **No malware scan.** Every file is recorded as "clean" and `application/octet-stream` is accepted. — AC: an EICAR test file is rejected or quarantined, and quarantined files cannot be downloaded.
- NFR-OPS-007: **Structured request logging and metrics.** JSON log line per request (request id, user id, portal, route, status, latency) with no secrets or PII; RED metrics; worker queue depth and age. Today logs are plain console output and mail tokens appear in logs when SMTP is unset. — AC: every request produces one JSON log line; no token appears in any log.
- **DEF-515** **No database or file-store backups** in the deployment. — AC: a scheduled MySQL dump or binlog backup plus a file-volume backup with 35-day retention, and a documented restore test.
- **DEF-516** **No CI pipeline** (only a GitHub Pages workflow for the legacy static site). — AC: every push runs install, typecheck, smoke and e2e against an ephemeral database and builds the images.
- **DEF-517** **Orphan uploads.** `POST /api/v1/uploads` stores encrypted files whose ids no endpoint consumes; they can never be downloaded or cleaned up. — AC: either domain endpoints accept `uploadId`, or the route is removed; unreferenced files older than 24 h are purged.
- **DEF-518** **Worker not started in development.** `npm run dev` does not run the outbox worker and there is no script for it, so local email, notifications and screening never fire. — AC: `npm run dev` (or a documented `dev:worker`) starts the worker.
- NFR-AV-005: **Idempotent, single-delivery worker.** Claim rows with locking so several workers can run; handlers are idempotent (notifications are not duplicated on retry). — AC: two workers processing the same queue produce each notification exactly once.
- **DEF-519** **MFA is off by default** (`mfa_required=false`). Step-up is skipped for users without a factor, so SRD 7.1 / NFR-SEC-008 approvals can run without a second factor. — AC: production default `mfa_required=true`, and a step-up-protected action by an unenrolled user returns `mfa_enrolment_required`.
- **DEF-520** **Invitation acceptance bypasses MFA** (it creates a fully verified session). — AC: when MFA is required for the portal, acceptance leaves the session MFA-pending with `mfa='enroll'`.
- **DEF-521** **Token TTL mismatches**: password reset 60 min (FR-AUTH-013 says 30), invitation 7 days (FR-AUTH-015 says 72 h). — AC: TTLs match the SRD, or the SRD is updated after a Q-NEW decision.
- Q-201: Should invitation and reset lifetimes follow the SRD (72 h / 30 min) or the code (7 d / 60 min)? — default: SRD values.
- **DEF-522** **BR-004 contradiction.** The code enforces at least one active System Administrator and flags more than two; BR-004 requires at least two `admin.rbac` holders and confirmation on system_admin changes. — AC: removing a role that would leave fewer than two active `admin.rbac` holders returns 409; the SoD scan flags fewer than two.
- **DEF-523** **Step-up status code**: 401 vs 403 (see 9.6). — AC: one status, used consistently by the API, bridge and SRD.
- **DEF-524** **Step-up missing** on cash-account approve, suspend, reactivate and close; document publish; capital publish; KYC activate. — AC: each returns `step_up_required` without a recent code.
- **DEF-525** **Audit gaps**: investor message post, public draft create/save, pre-case evidence upload, `/uploads`, step-up, failed logins, capital-evidence and company-file download URLs are not audited. The hash excludes actor role, portal, IP and request id. The table is not DB-protected against UPDATE/DELETE. — AC: every state change listed writes an audit row; the hash covers every column; the application DB user has no UPDATE/DELETE on `audit_events`.
- **DEF-526** **Investor account scope** is not applied to documents, capital events, requests or threads. — AC: a user with scope "documents" sees no capital events; a user with scope "managed" sees no private-fund documents.
- **DEF-527** **Company users are limited to their first linked company.** — AC: a user linked to two companies can switch between them (Q-01).
- **DEF-528** **Custodian portal** is deployed without auth, API or registry entry. — AC: the custodian portal is registered as a portal id, is in the CORS allow-list and has an auth gate before go-live, or is removed from the deployment.
- **DEF-529** **Investor and onboarding bridges are disabled.** The running UIs do not persist to the API (NFR-MNT-003). — AC: both portals load their bridge and the e2e journey passes through the UI.
- **DEF-530** **Dual-control gap on KYC decisions**: when no staff member has prepared a case, the preparer ≠ decider check is skipped. — AC: a case with no preparer cannot be decided until a different user has prepared it (or the submission counts as the preparer).
- **DEF-531** **Funds approval is automatic.** Approval sets `fundsApproved`, so the FR-ONB-010 funds gate never blocks. — AC: source-of-funds approval is an explicit, separately audited step.
- **DEF-532** **`.env.example` is stale** (missing file encryption, signing secret, SMTP, storage, idle-timeout and demo-seed variables). — AC: every variable the API reads is documented.
- NFR-SEC-013: **Portal security headers** (CSP, frame-ancestors none, referrer policy, permissions policy) at nginx or in Next.js. Today only the API sends helmet headers. — AC: every portal response carries the headers.
- NFR-SEC-014: **General rate limits**: 600 requests per minute per user and 30 uploads per minute per user (NFR-SEC-009). — AC: exceeding either returns 429.
